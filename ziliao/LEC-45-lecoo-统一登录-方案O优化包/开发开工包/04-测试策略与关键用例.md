# 测试策略与关键用例（方案 O）

## 策略

1. **契约优先**：OpenAPI 变更必须带用例。
2. **安全一票否决**：下列用例任一失败 → 禁止发布。
3. **分层**：单元（治理 store）/ 集成（Logto mock 或沙箱）/ E2E（登录漏斗）。
4. **不测 CAS**：相关历史用例全部删除或标记 N/A。

## 一票否决用例

| ID | 场景 | 期望 |
|----|------|------|
| SEC-01 | redirect_uri 不在白名单 | 拒绝授权，记审计 |
| SEC-02 | 缺 PKCE / state | 拒绝 |
| SEC-03 | refresh_token 重放 | 全链失效 |
| SEC-04 | client_secret 二次拉取 | 不可再取明文 |
| SEC-05 | 未授权租户访问成员 API | 403 |
| SEC-06 | 已禁用成员登录业务会话 | 拒绝 bootstrap |
| SEC-07 | 管理员踢人 | 业务会话立即失效 |
| SEC-08 | 开放重定向（//evil） | 拒绝 |
| SEC-09 | 权限目录写入不影响业务 API 鉴权旁路 | 目录仅展示 |
| SEC-10 | 审计事件不可物理删除 | API 无 delete |

## 功能冒烟

- 创建租户 → 邀请 → 接受 → 角色可见
- 注册应用 → 一次 secret → rotate
- 上报 permission-catalog → 管理端只读可见
- C 端「我的应用」宫格可进入（demo）

CI：lint + 单测 + `scripts/*-verify.mjs` 相关脚本；SEC-* 映射到自动化或手工检查表。
